## 🔒 機密情報の安全な共有方法

### 推奨される共有方法

#### 方法1: パスワード管理ツール（最推奨）

**1Password、LastPass、Bitwarden等:**

1. パスワード管理ツールで「Secure Note」を作成
2. 以下の情報を記録：
   - Supabase anon key
   - Supabase Database Password
   - Google OAuth Client Secret
3. 開発者を共有メンバーとして招待

**メリット**:
- 暗号化された状態で共有
- 履歴管理が可能
- アクセス権限の管理が容易

#### 方法2: 暗号化ファイル

**ZIP + パスワード:**

1. 情報を記載したテキストファイルを作成
2. ZIPファイルにしてパスワードを設定
3. ファイルとパスワードを**別々の方法**で送信
   - ファイル: メール
   - パスワード: SMS、電話、チャット等

**メリット**:
- ツール不要
- シンプル

**デメリット**:
- 手間がかかる
- パスワードの別送が必要

#### 方法3: セキュアなファイル共有サービス

**Google Drive、Dropbox等（リンク共有）:**

1. 情報を記載したドキュメントを作成
2. 共有設定を「リンクを知っている特定のユーザー」に限定
3. 開発者のメールアドレスのみアクセス許可

**メリット**:
- 簡単に共有できる
- アクセス制御が可能

**デメリット**:
- サービスのセキュリティに依存

### ❌ 避けるべき共有方法

- ❌ **メール本文に直接記載** - メールは暗号化されていない場合が多い
- ❌ **SMS/LINEに直接送信** - 履歴が残り、誤送信のリスク
- ❌ **スクリーンショットの共有** - ファイルに機密情報が残る
- ❌ **チャットツールに直接投稿** - 他のメンバーに見られる可能性

## 📞 よくある質問（FAQ）

**Q1: パスワードを忘れた場合はどうすればいいですか？**

A: 各サービスの「パスワードリセット」機能を使用してください。
- GitHub: https://github.com/password_reset
- Supabase: ログイン画面の「Forgot password?」
- Google: https://accounts.google.com/signin/recovery

**Q2: anon keyやClient Secretを紛失した場合はどうすればいいですか？**

A: 各サービスのダッシュボードから再度確認・再発行できます。
- Supabase: Settings → API
- Google Cloud: 認証情報 → OAuth 2.0 クライアントID

**Q3: キーが漏洩した可能性がある場合はどうすればいいですか？**

A: 
1. **速やかに開発者に連絡**
2. Supabase、Google CloudでAPIキーを**再発行**
3. Vercelの環境変数を**新しいキーに更新**
4. 再デプロイして反映

**Q4: 開発者を変更する場合はどうすればいいですか？**

A:
1. 各サービスで**旧開発者のアクセス権限を削除**
   - GitHub: Settings → Collaborators → Remove
   - Supabase: Settings → Team → Remove member
2. 新開発者を同様の手順で招待
3. 必要に応じて、パスワード・キーを再発行

**Q5: 有料プランへのアップグレード時期は？**

A: 以下の状況になった場合、アップグレードを検討してください：
- データベース容量が500MBに近づいた（Supabase）
- 帯域幅が100GB/月に近づいた（Vercel）
- 1週間アクセスがなくてもプロジェクトを停止したくない
- 商用サービスとして本格運用を開始する
